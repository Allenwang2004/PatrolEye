# PatrolEye v2: app, Supabase and camera

This is the contract shared by the app, the backend and the camera. Tables, RPCs, Storage paths, command formats and mask coordinates are defined here; if any side needs to change one, change this document first.

## Goals (before the final round)

1. The user signs up in the app and pairs a camera by scanning its QR code.
2. First-time setup runs a global scan; the user draws boxes on the panorama around areas that must not be seen. From then on those areas are always black in everything the camera captures (AI judging, recording and uploads alike).
3. The camera patrols on its own; when it finds something abnormal it records a clip (10 s before + 15 s after) and uploads it with a text description.
4. New events appear live in the app's event list; tapping one plays the clip.

## Not for now

- Push notifications: instead the event list updates live and shows an in-app alert while the app is open
- Inviting family, unpairing and reset, expiry and attempt limits on the claim code
- Wi-Fi provisioning (the camera is already online)
- Live streaming (not planned; event clips only)

## Architecture

```
Camera (Pi)                                     Supabase                          Phone (Expo app)
 live.py   camera, pan-tilt, masks, patrol,       Auth: user accounts, device       Sign in
           clip recording                         accounts                          Camera list
   ^ |  localhost HTTP         outbox/            Postgres + RLS                    QR pairing
   | v                                            Storage: panoramas, clips         Scan, draw masks
 agent.py  sign-in, heartbeat, pairing,  ----->   Realtime: events, commands,  <--  Event list, clips
           commands, uploads                      state
                                                  RPC: claim_device
```

- The camera opens no inbound ports; `agent.py` connects out to Supabase (HTTPS). `live.py` listens only on 127.0.0.1.
- Each camera has its own "device account" in Supabase Auth, and RLS uses it to limit the camera to its own data; users on the phone only see cameras they have paired.
- The service role key is used only by the provision script on the developer's computer, never in the app or on the camera.

## Terms

| Term | Definition |
|---|---|
| `device_id` | The camera's UUID (`devices.id`) |
| Device account | Email `device-<device_id>@devices.patroleye.local` with a random 32-character password. Stored only in the camera's `device/config/device.json` |
| `device.json` | `{"supabase_url", "supabase_anon_key", "device_id", "email", "password"}`, written by the provision script |
| Claim code | 8-character pairing code from the alphabet `23456789ABCDEFGHJKMNPQRSTUVWXYZ` (without the easily confused 0 O 1 I L), generated by the camera |
| QR content | `patroleye://claim?d=<device_id>&c=<claim_code>` |

## Tables (public schema)

| Table | Main columns | Written by | Read by |
|---|---|---|---|
| `devices` | `id` uuid pk, `device_user_id` uuid (auth.users, unique), `owner_id` uuid null, `name`, `room`, `claim_code` null, `created_at`, `claimed_at` | Created by the provision script; paired by `claim_device`; owner edits name and room | Owner, the device itself |
| `device_state` | `device_id` pk, `last_seen`, `status` (idle / patrolling / scanning / error), `masks_version` int, `app_version` | Device | Owner, device |
| `device_commands` | `id`, `device_id`, `type`, `payload` jsonb, `status` (pending / running / done / error), `result` jsonb, `created_at`, `updated_at` | Owner inserts; device updates status and result | Owner, device |
| `scans` | `id`, `device_id`, `pano_path`, `width`, `height`, `pan0`, `pan1`, `tilt0`, `tilt1`, `px_per_deg`, `created_at` | Device | Owner, device |
| `masks` | `id`, `device_id`, `scan_id`, `version` int (increments per device), `rects` jsonb, `created_at` | Owner | Owner, device |
| `events` | `id` uuid (generated by the device), `device_id`, `ts`, `type`, `severity`, `title`, `detail`, `checkpoint`, `clip_path`, `thumb_path`, `meta` jsonb, `acked_at`, `acked_by` | Device inserts; owner only changes `acked_at` and `acked_by` | Owner |

RPCs:

- `claim_device(p_device_id uuid, p_code text)`: called by the user. If `owner_id` is empty and `claim_code` matches, sets `owner_id = auth.uid()`, `claimed_at = now()`, `claim_code = null`; otherwise returns the error `invalid_claim`.
- `device_set_claim_code(p_code text)`: called by the device; only works while it is not yet paired.

## Storage (private buckets)

| Bucket | Path | Contents |
|---|---|---|
| `panoramas` | `<device_id>/<scan_id>.jpg` | Panorama, used for setting masks |
| `clips` | `<device_id>/<event_id>.mp4`, `<device_id>/<event_id>.jpg` | Event clips and thumbnails |

A device can only upload to its own `<device_id>/` folder; a user can only read the folders of their own cameras, and the app gets playback URLs with `createSignedUrl`.

## Commands (`device_commands.type`)

| type | payload | What the camera does | result |
|---|---|---|---|
| `scan` | `{}` | Global scan, stitch the panorama, upload it, insert a `scans` row | `{"scan_id": "..."}` |
| `apply_masks` | `{"mask_id": "...", "version": 3}` | Download the masks, store them locally, apply them immediately, update `device_state.masks_version` | `{"version": 3}` |

Status flow: `pending` when the app inserts it, `running` once the camera starts on it, then `done` (or `error` with `result = {"message": "..."}`).

## Panorama and mask coordinates

The panorama is an equirectangular projection (`device/panorama.py`) in the same angles as `scan.json` and `panilt.py` (degrees; positive tilt is up):

- Panorama pixel `(x, y)` maps to `pan = pan0 + x / px_per_deg`, `tilt = tilt1 - y / px_per_deg`
- `masks.rects`: `[{"pan0": -20.5, "pan1": 10.0, "tilt0": -30.0, "tilt1": 5.0}, ...]`, with `pan0 < pan1` and `tilt0 < tilt1`
- Drawing boxes in the app: convert screen coordinates to panorama pixels (multiply by `width / displayed width`), then to angles.
- Applying them on the camera: from the current pan-tilt angles, map each pixel back to a direction and black it out if it falls in any box (the formula is in `CAMERA_TODO.md`).

## Events

| Column | Values |
|---|---|
| `type` | `stove_on`, `person_down`, `gauge_high`, `leak`, `light_fault`, `valve_closed`, `other` |
| `severity` | `info`, `warning`, `critical` |
| `title` | One sentence, shown in the app's list |
| `detail` | The model's explanation |
| `checkpoint` | Checkpoint name, e.g. `STOVE`, `FLOOR`, `PT-101` |
| `meta` | e.g. `{"reading": 7.8, "unit": "bar", "confidence": "high", "looked_closer": true}` |

- Clips: H.264 MP4, at most 1280x720, 10 fps, 10 s before + 15 s after (including the turn and zoom), with masks applied; JPG thumbnail.
- The same abnormality at the same checkpoint is sent at most once every 10 minutes.

## Online status

The camera updates `device_state.last_seen` every 30 seconds; the app treats a device as online if it was updated within the last 90 seconds.
